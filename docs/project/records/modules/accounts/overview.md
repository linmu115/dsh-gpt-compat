# CPA 账号与固定代理

2026-10-06 后续：已安装GPT `.3` / Accounts `.4`，在认证失效账号卡片补充“重新登录”；复用现有登录接口并保留目标上下文，回调后核查原账号额度，失败或超时可重试。旧轮转模式禁用入口以避免隐式暂停，正常固定模式不切换账号。实际按钮/布局及受控回调后真实认证失败提示通过，真实OAuth仍待用户完成，见 [[IMP-relogin-20261006]]。

2026-10-06：已安装Accounts `.4`与GPT `.2`，加入可选白名单认证原因，并区分额度查询401与CPA管理密钥错误。实际账号401/token_expired及页面重新登录提示已验证；固定账号不变，账号重新登录仍由用户完成。旧快照/未知原因兼容，原始错误不公开。见 [[IMP-account-ui-20261006]]。

2026-10-03 更新：配置管理密钥先以候选值验证账号列表和固定路由契约，再单次提交凭据；第二步 401/404/无效载荷均保留原凭据。整个配置仍在同一串行操作队列中，不通过读取旧密钥完成候选验证。6 个新增回归先复现旧问题，修后账号测试 14/14 通过；未用真实账号执行失败写入；根任务负责固定账号实际验收，不改变固定账号选择，安装后凭据/账号保持，并通过正式 localStart 恢复停止的CPA。发行验收见 [[IMP-maintenance-20261003]]。

2026-09-18 新增明确需求：CPA 停止时，在此设置区显示服务状态并提供“启动本机 CPA”。后端只启动部署者配置的本机程序，等待实际响应，合并重复点击；已运行不重复启动，失败展示原因。不得借启动改动账号选择或登录凭据。验收包含未运行、已运行、启动失败和页面反馈。当前实现与部署结果见后续本次验证记录。

用户于 2026-09-17 明确要求：设置区显示当前 GPT 账号和额度，可以新增、移除账号；平时只代理指定账号，不在账号间轮换。新增账号与设为当前账号是两个操作。

设置面板通过 DSH 认证接口调用可选账号模块，模块使用服务器 credentials 调用 CPA 管理接口。CPA 持有 OAuth 凭据，并在重试前固定请求账号。额度不足、账号缺失或失败时停止；已经发出的请求保留原选择。额度未知不显示成零，移除前确认具体账号。

账号控制与 Maintenance 会话扩展数据互不替代；后者继续使用已有 `gpt-compat` 扩展数据 Adapter，不新增 Harness Adapter。本模块不复制 access/refresh token，也不改变宿主会话格式。

安装、接口归属与使用边界见 [账号接入说明](../../../../accounts.md)。源码入口：`src/accounts/host.ts`、`src/accounts/cpa.ts`、`src/client/Accounts.tsx`；CPA 独立补丁及权威合同随仓库提供。验收见 [[VER-accounts]]。

模型发现同样通过管理接口只读完成：将账号可用型号与 CPA 容量、推理能力资料取交集，交给原生 Responses 目录；固定账号、暂停与失败边界见 [[IF-profile]]。账号操作和发现变化会刷新会话目录。此能力的验证单列于 [[VER-model-catalog]]。
