# 从模型绑定表单改为自动目录的开发过程

本任务由原设置页的模型文本框问题开始。当前结果见 [[IMP-current]]，验证范围见 [[VER-model-catalog]]；本记录补充实现过程中怎样改变方案、遇到问题并完成交付。

## 1. 先澄清设置区到底负责什么

用户最初要求把模型文本框改为下拉框，并描述“点击模型切换”。该文本框原本控制哪些模型启用兼容，而会话页也有实际模型选择器。助手发起澄清，并曾写出尚未交付的下拉编辑草稿。用户随后明确：这里自动提供 GPT 的全部模型，不需要选择或填写，真正的选择留在会话页面。

[查看依据：用户明确撤销设置区选择与填写](history-event:EVT-a9915ffacacdeafd0441)

因此放弃下拉编辑草稿，改成只读目录加刷新按钮。这是需求澄清后未采用的方案，不是下拉框经过验收后被判定失败。可复用的边界判断见 [[EXP-model-settings-boundary]]。

## 2. 不能只移除输入框，后台范围也要改变

原后台只登记了三个手填型号；仅隐藏表单仍会限制会话页的可用模型。实现改为把 CPA 账号可用目录与容量、推理能力资料取交集，由 Responses 适配器向 DSH 提供模型目录。兼容范围依据本插件注册的提供商身份自动生成，同时供工具和上下文路径使用，不接管其它提供商的同名型号。

固定账号只读该账号目录，暂停返回空目录，缺失容量或发现失败拒绝。图片生成型号不进入会话模型列表；普通、未连接发现服务的 Responses 配置仍沿用显式能力配置。范围与测试结果见 [[IF-profile]]、[[VER-model-catalog]]。

[查看依据：新增发现逻辑后的全量离线测试结果](history-event:EVT-d52d9f54495be7be15c8)

## 3. 构建成功之后，真实插件加载仍失败

后台已经返回五个型号，客户端也已通过构建；首次安装后浏览器却显示插件加载失败。实际错误为 `cannot get property "remote" without inject`：客户端访问 `ctx.remote`，依赖声明却只有 `remote.session`，遗漏了根服务。

[查看依据：真实副本页面的加载错误](history-event:EVT-5bbba2e972c9cbbc763c)

修复补齐 `remote` 和 `remote.session`，同时使账号变化和目录变化通知会话选择器刷新。重新构建、相关 14 项测试通过后，正式安装到副本并重新生成、验证 Maintenance 接入材料。这里没有放宽格式检查来跳过启动问题。经验见 [[EXP-client-service-injection]]。

[查看依据：修复后的构建与 14 项相关测试](history-event:EVT-afab5ebeb6ddd90bb5b4)

## 4. 分开判断产品故障与验证脚本故障

副本页面验证确认：五个 GPT 会话型号只读展示、刷新可用、没有模型或提供商输入框；两个账号可见，50 个非空会话保留，19 项绑定文件通过校验，主实例未改动。

[查看依据：实际页面与副本保留检查](history-event:EVT-8d2cbf727f5b888833b7)

检查会话菜单时，第一版脚本按一次 Escape 后再次点击触发器，等待推理等级菜单超时。读取宿主源码发现 Escape 先返回上一级；随后点击触发器反而关闭菜单。因此修改的是验证脚本，改为点击菜单外部关闭，再打开推理列表。没有据此重写正常工作的宿主菜单。

[查看依据：菜单检查的超时反馈](history-event:EVT-81f2650fd6e8ddc7ac79)

[查看依据：Escape 行为源码与修订后检查通过](history-event:EVT-798a02a977303a0c2923)

最终会话页可见五个模型和当前型号的推理档位，验证没有改动用户当前选择。此阶段未逐型号发送真实生成请求。经验见 [[EXP-menu-verification-state]]。

## 5. 交付后又发现地图维护遗漏
