# 给 CPA 账号设置增加本机启动入口

用户发现 GPT 连接可能因 CPA 未启动而失败，要求在 DSH 设置信息页提供启动按钮。检查本机 8317 端口和进程均未发现 CPA，因此在已有 CPA 账号面板新增服务卡片，保持现有 DSH 组件和主题。

后台启动只消费部署者设置的程序、配置和密码文件路径，页面仅发送动作。先确认本机端点，再检测同路径进程，用独占锁和共享等待防止并发重复启动；隐藏窗口并分离进程，等待 CPA 实际回应。账号与模型列表在就绪后刷新，已运行、未配置、启动失败和超时分别反馈。模型会话、固定账号选择与 GPT 登录凭据不由启动动作修改。

验证通过了类型检查、85 项测试、发行包导入和真实离线检查。最初尝试通过副本 profile 的正式热更新加载账号模块，但当前进程仍返回旧接口的 invalidInput，未把文件写入当作成功启用。遵守当天工作区约定，没有使用直接 runtime shutdown 或强杀。

用户随后告知已停止实例。核验维护数据库 closed、Launcher finalized/closed 和实例离线后，完成账号模块 0.1.1 与客户端增量安装，备份配置、包及正常关闭后的维护数据库；原有 19 个格式绑定固定文件校验保持不变。客户端基线仍是 dev.8，增量以单独发行路径及文件指纹区分。

正式 Start 两次等待未取得新实例身份。用户提示隔壁也在操作 Launcher，因此停止继续尝试，向“评估插件实例与仓库绑定方案”任务交接。对方随后确认接管，说明正在通过正式修复接入操作处理并行插件更新造成的 fingerprint 失配，并承诺单次启动后回告运行身份。本任务不再改 profile 或发起生命周期命令，只在新运行可用后验证 CPA 按钮。

这次没有把源码测试、包已复制或 Launcher 已收到命令当作真实 UI/启动验收。当前安装与验收边界集中在 [[VER-cpa-start]]。

后续运行态检查：隔壁修复接入并启动副本后，实际点击返回 localConfigInvalid；CPA 仍未运行。OS 和离线合成配置中的三个文件均存在，所以未断言具体根因。补充了逐文件检查提示，另发现 Windows 正反斜杠会影响进程路径比较，修订为统一规范化后再查询。针对测试通过，等待隔壁引擎升级的正常停止窗口安装，不重复操作 Launcher。此段为本任务后续公开检查补充，原索引覆盖范围仍以元数据为准。

收到隔壁提供的正常停止窗口后，先再次核验 stopped 并备份当前两包与依赖锁，仅安装 0.1.2 账号模块和客户端增量。没有修改引擎、生命周期钩子或 cordis.patch.yml；安装完立即交还控制权。随后完整测试为 87 项通过、1 项跳过，等待统一启动后继续真实按钮测试。


隔壁完成 Engine .40 升级后，0.1.2 运行态明确返回 localPasswordMissing。静态路径、同一用户 SID 与文件 ACL 检查不能解释差异。本任务随后尝试通过 Node inspector 读取实际路径；诊断表达式中的动态 import 在该环境不支持，清理表达式产生未捕获拒绝，触发 DSH fatal load failure 并导致副本退出。这个故障由诊断操作造成，已主动告知用户与隔壁，不归因于原 CPA 功能。隔壁只读确认旧 run recovered、handle finalized/recovered，之后交由本任务单一控制恢复；没有把异常恢复写成正常关闭。

改用插件自身的脱敏错误日志，发布 0.1.3，记录文件错误码、路径长度和 SHA-256，去重且不输出原路径或错误正文。备份并安装后通过官方 repair 刷新指纹，正式 Start 恢复 running。此次检查拿到 ENOENT；运行时路径指纹与独立 Node 的路径完全一致，独立 Node 却能看到文件。没有继续向运行进程注入诊断代码，也没有在没有证据时断言权限或配置转换是根因。

将同一管理密码复制到 CPA 目录的私有子目录，沿用原文件/目录访问权限，并加入本机 Git 排除；只热更新 localLaunch.passwordFile。状态立即变为可启动，没有为此重启 DSH。真实浏览器点击一次后 CPA 已运行，账号列表恢复为固定模式、2 个账号；重复请求仍只存在一个 CPA 进程。浅色、暗色和 320px 卡片截图通过，未发模型请求或改账号选择。最终全套 88 项测试通过、1 项网络测试跳过。原 AppData 可见性差异的底层原因仍未查明，保留为已恢复可用但根因未定的边界。

来源快照之后的收尾：凭据路径变更触发接入指纹失配，核对官方 repair 的副作用后在线修复，备份 hook、required 策略与绑定。接口不是仅写指纹，还会重写既有 hook/required 文件；修复后核验内容、其他绑定、范围、19 个固定文件与同一 boot/run 均保持不变，接入 connected。收尾校验脚本曾使用错误的结果字段导致报告生成失败，未重复执行修复动作，改用只读校验确认上述结果。
