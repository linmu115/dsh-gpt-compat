# 检查点与上下文交付合同

这个接口保证换模型后继续的是最新工作。它让提供商拿到本路线能读懂的上下文，同时防止原生密文进入其他模型、通用摘要进入 GPT 原生路线。

提供方为 [[MOD-context|两版压缩模块]]，消费者为 [[MOD-provider|提供商适配]] 与宿主请求组装入口。宿主在冻结前调用选择器，记录并持久化投影，再发送；同时检查所有权、取消和源历史是否变化。

输入包括会话原始历史位置、当前路由兼容信息、各路径已有检查点、有效模型容量和固定提示/工具开销。输出包括完整请求窗口、所选检查点身份及覆盖范围、尚需追加的历史和预算状态。

| 情形 | 必须行为 |
|---|---|
| 无检查点且原文装得下 | 直接交付目标协议可读取的原始历史 |
| 有兼容检查点 | 使用该检查点的完整窗口，加其后新增历史；防止保留项重复 |
| GPT 回切增量过大 | 按顺序分批原生压缩，直至覆盖当前历史位置 |
| 检查点不兼容 | 从保留历史重建目标路线，不转发其他提供商专用状态 |
| 压缩失败或取消 | 不提交半成品，不改变另一侧已提交结果 |
| 停用或重启 | 原始历史和通用读取可用；专用检查点只能按兼容条件恢复 |

检查点 state 保存 version、covered、digest，以及 native 或 summary。context/checkpoint-commit 引用已经持久化的候选序号；未提交候选不参与选择。request/projection 保存准确消息及可选 adapterContext，后者的 format/scope 在 LLM 发送边界校验。压缩输入与结果也分别记录为 context/operation 和 context/operation-result。新事件要求具有宿主补丁的读者，不支持旧宿主降级恢复。

两条路径独立调度，共享原始历史；并不需要同时改写一个活动摘要。通用压缩所用模型可以配置，不等于必然在本机推理。

原生协议模式属于检查点兼容身份。responses 模式使用远端计数；codex-v2 使用带裕量的本地估计，不能把估计当作准确用量。v2 保留用户原文，无法满足预算时失败；不静默丢弃原文或转成通用摘要。


## 图片上下文（0.5.0-dev.4）

用户消息与工具返回的图片以 DSH 持久附件引用进入原生投影；只在 HTTP 发送边界通过附件服务校验并读取字节，转换成 Responses input_image。普通发送、远端计数、独立 compact 与 codex-v2 共用这条转换路径。读取失败、取消或请求字节超限会中止，不静默过滤图片。

Core 0.3.12-rc2.13 在适配器缺少 imageRequestPricing 时按每次出现预留 4096 token；适配器已返回错误结果仍拒绝。GPT 适配器公开估算接口：每图至少 4096，较大图片按 32 像素格估算并留余量；v2 总预算再乘配置的估算乘数。估算不是计费值或严格上界，不按 base64 长度计作文字 token。通用摘要预算同样计入图片。

v2 压缩请求包含被覆盖的图片。只有成功获得完整加密检查点后，保留窗口中的旧图片才转成“已包含在压缩上下文”的文字标记，用户文字原样保留。原始会话附件不删除；近期保留组的图片仍原样发送。独立 compact 的完整返回窗口不丢弃，已知回传图片恢复成持久引用。通用摘要明确要求保留与任务有关的图片内容和文字标签。

依据：[Responses 请求约定](https://developers.openai.com/api/reference/cli/resources/responses/methods/create)。真实 CPA 合成图通过发送、压缩和恢复接续，尚未用用户会话做发送验证；图片摘要仍有信息损失，不能宣称所有视觉细节无损。
