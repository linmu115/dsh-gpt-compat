# 激活与请求配置合同

这个接口让一次模型请求从提示词到工具结果始终使用同一套兼容配置。比如用户在请求执行中换模型，正在执行的工具仍按旧快照完成，新选择在下一安全步骤生效。

提供方为 [[MOD-routing|绑定与启停模块]]；消费者为 [[MOD-tools|工具模块]] 和 [[MOD-provider|提供商适配]]。消费者通过每步捕获的路由与工具作用域协作。

| 方向 | 语义内容 |
|---|---|
| 输入 | 会话身份、当前提供商与模型、本插件提供商目录、其它路线的显式绑定、宿主能力、步骤与取消信号 |
| 输出 | 是否启用、匹配策略、固定的协议与工具呈现、作用域身份和撤销责任 |
| 状态变化 | 匹配后准备与激活；选择变化待切换；当前调用收尾后撤销 |
| 可观察结果 | 当前生效配置、失败原因、所用版本与撤销结果可定位到会话步骤 |

匹配失败使用普通 DSH 配置。匹配成功但必要能力不支持时应明确暴露缺口，不能只显示已启用却漏掉必要工具。工具、提示词与最终请求路由不一致时不得发出混合请求。

接口变更影响工具可见性、已有进程句柄与历史结果解释，因此要核对三个消费者边界。配置 schema 与匹配规则见 src/config.ts 的 Config、withNativeBindings、matches、validateConfig；每会话启停见 src/index.ts 的 apply；模型连接快照由 src/responses.ts 的 prepareCall 固定。已有宿主事件不能被旁路改写。

工具作用域、选择冻结和原生 Responses 请求/返回协议均已实现，副本完成真实工具调用；Maintenance 扩展数据 Adapter 已在副本验收。具体边界与证据见 [[IMP-current|当前实现]]、[[VER-tools|工具首版验证]]。

## 自动模型目录与兼容范围

例如 CPA 增加一个 GPT 会话型号后，刷新设置目录可读到该型号及其容量、推理档位；用户在会话页选择它，后续步骤自动启用兼容工具。设置页本身没有型号选择或绑定编辑操作。

路由模块通过宿主提供商目录识别 `gpt-responses` 所有权，为这些提供商计算 GPT 范围，同时交付给工具与上下文模块。其它提供商的同名型号不自动启用；其显式绑定仍按原规则处理。

模型发现由 [[MOD-accounts]] 提供账号可用列表与 CPA 能力资料，[[MOD-provider]] 转换为 DSH 模型目录与请求能力。固定账号只使用该账号的目录，暂停时为空；已连接的发现链失败或缺少容量时拒绝，不能用猜测容量或旧手填列表伪装成功。未接入账号模块的普通 Responses 路线保留原显式配置。

账号操作或检测到目录变化后通知会话选择器刷新；已经准备的请求保持原快照。客户端依赖宿主的 `remote` 与 `remote.session` 服务，后端不得将管理凭据返回模型目录。验证范围见 [[VER-model-catalog]]。
