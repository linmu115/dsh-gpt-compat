# 原始历史与两种上下文

实现中原始会话事件是共同依据，包括用户输入、助手结论、工具调用与结果。原生压缩、通用摘要和工具呈现都不能取代这份历史。

| 对象 | 保存什么 | 所属与约束 |
|---|---|---|
| 会话原始历史 | 有序消息、工具配对、来源及必要状态 | DSH 持续保存，插件停用后仍能读取 |
| 激活快照 | 提供商、模型、绑定策略、协议与工具版本 | 每个步骤固定；选择变化在下一安全边界生效 |
| 原生检查点 | 服务端返回的完整压缩窗口、兼容信息、原始边界及用量依据 | 仅发给匹配的原生路线；不能用密文长度估算有效 token |
| 通用检查点 | 可读摘要、保留原文、覆盖边界及来源 | 普通 DSH 路线可独立读取，不依赖插件继续加载 |
| 历史增量 | 检查点覆盖位置之后的新工作 | 两条路线各自计算；接续不得遗漏、重复或截断工具配对 |

历史边界相同不是前提。GPT 已多次压缩时，较大容量模型仍可能直接读取原始历史。任何检查点只有成功生成、校验并持久化后才生效。

兼容判断、预算和切换重建的合同见 [[IF-context|上下文交付]]；完整用户要求见 [[REQ-gpt-compatibility|规格]]。
