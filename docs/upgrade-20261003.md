# 2026-10-03：增量交付、压缩用量与显式服务端压缩

目标候选为 GPT `0.6.0-dsh02.1`，继续面向准确 DSH `0.2.0-rc.2`、Cordis `4.0.4` 与独立宿主 `gpt-dsh02.1`。上一轮 `.2` 进程/账号修复及安装记录保留在 [maintenance-20261003.md](maintenance-20261003.md)，不将本轮候选写成已安装。本轮根任务负责完整回归、发行、实际模型与浏览器验收；当前文档记录实现及离线验证边界。

## 三项升级及合同

1. Responses SSE 在终态之前交付文本/推理增量；完整终态与工具参数验证仍是执行工具的前提。取消、截断、矛盾终态不得留下可执行的半个工具请求。实现和对应测试由流式分工维护，普通JSON响应继续支持。
2. 独立压缩请求显示额外用量，与宿主普通响应统计分开。新增只读诊断卡，将配置能力、固定账号协议读取和CPA公开标识分别显示；不把“已配置”当作模型请求或端点能力已验收。
3. 新模式 `responses-server` 及阈值为显式选择，默认不改变当前CPA `codex-v2`。服务端压缩项通过经过验证的replay保存和裁剪，不放宽普通模式。`serverManaged` 标记使上下文选择从完整原始历史重建，不复用旧本地摘要/检查点投影，也不再次执行本地count/compact。

服务端端点支持另行验证。当前CPA的翻译路径可能删除 `context_management`；诊断不会硬编码所有CPA都不支持，也不会因发送参数成功或模式配置成功宣称端点已执行压缩。

## 辅助用量持久化

插件内 `NativeContextExtras.compactWithUsage()` 返回同一压缩请求的 `{input, usage?, accounting:'auxiliary'}`，旧 `compact()` 保持兼容。旧宿主能力没有扩展时仍可运行，但该次用量明确未知。原生独立compact、CPA codex-v2压缩和portable-summary均将已返回用量写入现有 `context/operation-result.output`：

```text
{type:'gpt-compat.compaction-result', version:1, result:<原输入窗口或摘要>,
 usage:{accounting:'auxiliary', inputTokens, outputTokens, totalTokens,
        cacheReadTokens, cacheWriteTokens, reasoningTokens}}
```

缺失或非法计数写为 `null`，不填0。`inputTokens` 遵循宿主“未缓存输入”语义；推理token是输出的组成部分，不再加到输出上。额外统计只汇总独立操作、按operation去重；任一缺失项使相应总量保持未知。流内服务端压缩属于普通响应用量，以 `included-in-response` 说明，禁止再次加入辅助总计。不推算价格或声称总成本完整。

现有V4事件种类、checkpoint version1/native input及提交流程不变；旧数组/字符串operation-result仍可读取，统计显示未知。压缩记录UI只从事件提取计数与公开方法元数据，不把summary、prompt或opaque拷入渲染状态。旧历史不需要批量迁移。

## 只读诊断

`GET /api/gpt-compat.diagnostics` 注册在Connection现有认证及Host/Origin校验边界内，返回 `Cache-Control:no-store`。拒绝其他方法和查询参数。返回上下文开关、绑定数量、提供商模式、声明的容量/推理档位、固定账号协议状态及CPA公开身份结果；不返回管理密钥、key reference、账号ID、端点路径、prompt或opaque。

固定账号状态通过现有只读identity接口判断；不调用configure/switch/login/localStart，也不发模型请求。CPA仅对本机HTTP地址读取公开根标识，拒绝重定向，限制响应16KiB。无法判断明确停止时显示“不可用”，提示到账号管理检查本地代理并按需启动，诊断不会代为启动。服务端请求3秒上限，界面5秒上限，刷新手动触发，卸载取消旧请求。
